## 1. 完成定义

阶段 0 收尾不要求消灭所有环境限制，而要求对每项风险给出一种明确结果：实机通过、自动化覆盖并接受残余风险、推迟到发布前回归，或因硬件不可用而延期。

正式关闭阶段 0 前至少应满足（不阻塞可安全并行的 Stage 1 视觉工作）：

1. 安全自动回归持续通过；
2. 原生全屏状态至少取得一次 `no → yes → no` 实机证据；
3. 不把会话切换误报为普通锁屏，并明确未来 idle 延后与自然休息取消语义；
4. 睡眠与显示器息屏完成一次实测，或明确接受延后风险；
5. 浮层在当前深浅外观下不抢焦点、不拦截输入；
6. 长时资源采样没有持续内存增长或异常 CPU；
7. 多显示器因缺少硬件延期，不得用单屏或纯几何测试冒充实机通过。

## 3. 集中到一次短暂人工窗口

### 原生全屏，约 2 分钟

运行：

```sh
./scripts/run-stage0-manual-test.sh fullscreen 90
```

期间进入一个原生全屏窗口、停留 5 秒，再退出并停留 5 秒。验收结果必须同时包含 `no` 和 `yes`，并根据时间顺序人工确认 `no → yes → no`。

### 锁屏，约 2 分钟

运行：

```sh
./scripts/run-stage0-manual-test.sh lifecycle 120
```

普通锁屏没有可靠的公开事件，不再要求或伪造 `session_locked`。本场景保留用于未来行为引擎验收：提醒到期后锁屏时不得展示或消耗本周期提醒；不足 5 分钟解锁后重新判断，超过 5 分钟则取消旧提醒并重置周期。

### 睡眠和显示器息屏，约 5–10 分钟

用同一 lifecycle 命令延长时间，保存工作后再触发。系统睡眠使用真实事件；仅显示器息屏使用 `displaySleepState` 的 `no → yes → no` 状态序列，屏幕通知只作为可选提示。

### 外观，每种设置约 10 秒

切换深色/浅色、减少动态效果、增强对比度或减少透明度后分别运行：

```sh
./scripts/run-stage0-manual-test.sh appearance
```

每次确认输出反映当前设置，浮层文字可读，前台应用未改变，点击仍可穿透。

## 4. 长时资源验证

正式运行：

```sh
./scripts/start-long-resource-test-detached.sh 28800 60
```

后台启动器把自包含探针放到 `/Users/Shared/FocusBreakAssistant-Test`，避免 Documents 隐私隔离，并通过用户 LaunchAgent 脱离 Codex/终端会话。脚本每分钟记录 RSS 与 CPU，并保留 1 Hz 隐私最小活动快照。验收重点是 RSS 不持续单向增长、平均 CPU 足够低。该脚本不宣称测得 macOS Energy Impact；最终能源结论仍需结合 Activity Monitor Energy 面板或 Instruments System Trace。

- 所有延期项继续保留在手动日志中，不因进入视觉原型阶段而删除。

## 6. 推进顺序

1. 立即完成安全自动回归和短时资源采样；
2. 用户方便被打断时，一次完成全屏与短时锁屏；
3. 空闲或夜间完成睡眠、息屏和 8 小时资源测试；
4. 长时资源测试转为后台验收，同时并行进入 Stage 1 Horizon Gap 视觉提醒原型；
5. 资源结果无异常，已记录风险接受并关闭阶段 0；Stage 1 期间不提前实现完整行为引擎。
